## 1. 背景与目标

测试环境（esg-ai 仓库）已实现一版"指标信息采集表"功能（上传上交所采集表模板 → 提取定量指标 → 匹配平台指标 → 人工确认 → 自动回填生成 Word），但与需求文档 §6.4 存在多处分歧：首次使用强制上传映射表、确认表仅 5 列且无数值来源信息、人工修改的数值会被重匹配冲掉、匹配不上的行因必填校验卡死、确认的映射关系未回写平台知识库映射列表等。

经 2026-09-09～09-11 会话对测试环境代码逐项审查与拍板，形成本版目标态：映射表改为可选、确认表扩为 7 列、人工数值不可覆盖、允许无映射手工行与空值、映射确认时双写（全局映射库＋知识库映射列表）、采集表模式附件类型收窄。开发将基于测试环境代码做增量修改到达该目标态。

## 2. 功能点

- **FP-1 入口与模式**：仅管理员可见的全局 AI 助手【指标信息采集表】按钮；进入后顶部模式提示条＋欢迎语说明流程（沿用全局规则 7）。
- **FP-2 模板与映射表提供**：模板必传（📎 本地上传或 🗂 知识库引用，硬校验 DOCX）；映射表可选（同两种来源，知识库中任意 xlsx 文件均可，硬校验三列 XLSX 且整表恰好一个合规映射区域）；全局映射库为空也可直接使用。
- **FP-3 附件两层校验**：第 1 层沿用全局（≤100MB、不含音视频/gif）；第 2 层采集表模式收窄为仅 .docx/.xlsx，错型当场报错，模板槽/映射槽错配当场提示。
- **FP-4 非认证模板兜底**：模板结构与认证库不符时停在"模板结构人工确认"卡（AI 预分类＋人工核对列号/单位/版本号），确认后入认证库；标准上交所模板不经过。
- **FP-5 匹配优先级与冲突处理**：逐行"上传映射表 → 全局映射表 → 大模型语义匹配（top3）"，前级命中即采用；失效映射按未命中处理；语义匹配候选按置信度阈值过滤（后端固定常量，暂定 0.5，候选为空按"未匹配"处理）；五类冲突规则（见 §3 流程 B）。
- **FP-6 确认表**：7 列结构（附件定量指标名 / 平台对应指标名 / 平台对应指标编码 / 本期数据 / 上期数据 / 匹配来源 / 是否采纳），top3 下拉带置信度、行级"已修改/已刷新"标记、超 6 行预览＋大窗编辑。
- **FP-7 提交确认循环与终确**：任务存在过任何修改时，点【确认】一律返回全量结果表供核对（本轮有修改先重匹配；零修改任务确认即填充）；填充仅经结果卡【✅ 确认无误，开始填充】显式触发；人工数值任何重匹配不得覆盖；并发乐观锁保护。
- **FP-8 填充与产物**：最终确认后按单元格坐标原位回填，空值跳过、不采纳行跳过；Word 下载卡片带 AI 标注与统计提示；回填自检不通过阻止发布。
- **FP-9 映射沉淀**：确认时同一事务内双写——①全局映射库（只收"采纳且有平台编码"行，失效旧映射停用）；②知识库映射列表（关联模板＝本次模板、确认状态＝已确认、指标映射数＝本次入库条数；同一模板再次确认时更新同一条记录，不新建重复记录）。
- **FP-10 知识库映射表管理（6.1.7 联动）**：菜单仅管理员可见；行内【查看】以三列表格渲染映射明细（附件定量指标名 / 平台对应指标名 / 平台对应指标编码）；【下载】下载映射表文件；【删除】仅管理员可删，仅移除知识库展示记录、不联动全局映射库。另单独维护一份「全局指标映射总表」：全局映射库当前全部有效条目的全量合并视图（三列），随每次确认覆盖刷新同一条置顶记录（关联模板显示"全局"），系统自动维护、可查看可下载、不提供删除。

## 3. 交互流程（点击级）

### 流程 A：进入与上传（对应：全局 AI 助手对话窗口）

1. 管理员打开全局 AI 助手，点击输入区上方的【指标信息采集表】按钮（普通用户看不到该按钮，沿用全局规则 7）。
2. 顶部出现模式提示条，助手发送欢迎语说明流程。
3. 点击【📎】选择本地模板文件（必传），或点击【🗂】从知识库引用模板文件；确认后文件卡片显示在会话区；模板格式硬校验 DOCX。
4. （可选）以同样方式提供映射表：📎 本地上传或 🗂 引用知识库中任意 xlsx 文件；系统硬校验三列 XLSX——附件定量指标名 / 平台对应指标名 / 平台对应指标编码，三列必须同时填写、缺一报错；整表须恰好一个合规映射区域，否则报错。
5. 附件两层校验：第 1 层沿用全局（单文件 ≤100MB、不含音视频/gif）；第 2 层模式收窄——📎 选择器仅接受 .docx/.xlsx，选择其他类型（含全局白名单内的 pdf/ppt/jpg 等）在选文件瞬间报错提示；模板槽只认 docx、映射槽只认 xlsx，错配当场提示。
6. 发送后 AI 开始提取模板中所有需填写的定量指标并逐行匹配（见流程 B 规则）。

### 流程 B：匹配（优先级与冲突规则）

1. 匹配优先级（逐行生效）：① 用户本次上传的映射表 → ② 全局映射表 → ③ 大模型语义匹配（给出 top3 候选）。前一级命中且有效即采用、不再查看后级；某级映射因平台指标失效而无效时，跳过该级进入下一级。
2. 上传表与全局库并存：上传表覆盖到的行用上传表，其余行仍可用全局库兜底；上传映射表不屏蔽全局库。
3. 首次使用无前置条件：全局映射库为空也可直接发起，未命中映射的行全部由大模型语义匹配。
4. 有效性校验：映射指向的平台指标已改名/删除 → 该条按未命中处理 → 该行进入大模型语义匹配；确认时该失效旧映射在全局库中同步停用。
5. 候选过滤阈值：置信度不高于阈值的候选不进入候选列表；阈值为后端固定常量（暂定 0.5，不提供界面配置，后续按测试与算法校准由后端修改代码值）；某行经优先级匹配与阈值过滤后候选为空（搜索无结果或候选全部不高于阈值）→ 按"未匹配"处理（名/码空、可手填、不进映射表）。
6. 冲突处理五类：
   ① 上传表内部同名重复：解析时报错拒收（提示"附件定量指标名'××'重复"），用户改表再传；
   ② 上传表行内名码自相矛盾：运行时经有效性校验判定为无效，该行进入大模型语义匹配；
   ③ 上传表与全局库同名冲突：不是错误，按行上传优先；
   ④ 多个附件指标名指向同一平台指标（多对一）：合法，各行各自取数；
   ⑤ 全局库内部重复：由数据库唯一约束杜绝。

### 流程 C：非认证模板结构确认（兜底卡，标准上交所模板不经过）

1. 模板结构与认证库不符时，流程停在"模板结构人工确认"卡。
2. AI 预分类，用户逐行核对本期/上期数值列号、补单位、自拟模板版本号。
3. 确认后该模板结构入认证库，下次直通。

### 流程 D：确认表核对与循环确认（对应：会话内确认表卡片＋完整表格大窗）

1. 匹配完成后，会话中出现可编辑的确认表卡片；年份选择按钮（输入区排在【数据选择】之后，仅采集表模式显示）——选项＝平台全部收集年份（按收集年份字段由新到旧，第一项为最新），**默认选中最新收集年份**、不提供"自动"；年份一律经按钮显式选择（取消"消息中明示年份"判定）；所选年份与模板封面年度不一致时提示"请确认"后继续、不阻止；上期＝本期减一年；年份整表统一，两列列头标注所选年份；年份选择对下一次提取生效；**上传模板的年份不做限制**——提取按所选年份查收集数据，所选年份无任何收集数据时提示"所选年份（XXXX）暂无收集数据，请更换年份"、不生成确认表，更换后重新提取。
2. 确认表 7 列：
   ① 附件定量指标名——模板提取，只读；
   ② 平台对应指标名——映射硬匹配直填；AI 匹配给 top3 下拉：每个候选后带置信度分数，默认选中最高分（用户不选即最高分），都不对可手输文字；
   ③ 平台对应指标编码——随匹配带出，只读；
   ④ 本期指标数据（XXXX年）——平台查得到自动填，查不到留空；可手输；
   ⑤ 上期指标数据（XXXX年）——同本期列；
   ⑥ 匹配来源——映射表 / AI匹配 / 未匹配；
   ⑦ 是否采纳——默认采纳；选否则该行不填充、不进映射表。
   置信度不设独立列，仅随 top3 候选显示。
3. 状态列（行尾独立列，不占数据列）："已修改"＝用户在本工作流改过该行（改指标名 / 改或填数值 / 切换采纳），跨确认轮持续到工作流结束；"已刷新"＝该行本轮被 AI 重新匹配、身份或数值被服务端刷新，仅标本轮；"低置信"（橙色）＝该行当前默认/选中候选的置信度 < 0.85，提示重点核对（仅提示不阻断，与终确按钮构成双保险）；二次确认先扫"已刷新"再看"已修改"，低置信行重点核对默认匹配。
4. 超过 6 行时仅显示前 6 行＋提示行；点击【查看/编辑完整表格】弹出大窗承载全部编辑交互。
5. 用户手输的平台指标名再匹配仍未命中时：确认表中保留用户原文显示＋标"未命中"，匹配来源显示"未匹配"。
6. 点击【确认】提交：有变更的行（AI 待匹配、改过指标名的）→ 系统再查平台 → 返回全量结果表（同样 top3 下拉、默认最高分）。
7. 人工数值不可覆盖：用户填写/修改过的数值一经提交即为最终值，任何重匹配不得覆盖；改名行仅刷新指标身份与编码。
8. 匹配不上的终局（无映射手工行）：平台名/编码留空（手输原文保留＋"未命中"标记），数值可填可不填——填了正常填充，不填跳过写入、单元格留空；该行不进映射表。
9. 确认返回规则：本轮有修改 → 重匹配后返回全量结果表（变更行标"已刷新"）；本轮无修改但任务中存在过修改（含改过又取消弹窗）→ 同样返回全量结果表（提示"共 X 项，其中已修改 N 项"）；返回的结果卡均提供【✅ 确认无误，开始填充】按钮；并发冲突时版本乐观锁自动拉最新快照刷新重试。

### 流程 E：最终确认、填充与映射沉淀

1. 最终确认触发：任务存在过修改 → 仅经结果卡【✅ 确认无误，开始填充】按钮进入填充；全程零修改的任务首次【确认】直接进入填充 → 按单元格坐标原位回填原模板；空值跳过写入（单元格留空）；不采纳行跳过。
2. 会话中出现 Word 下载卡片：文件名＝原模板名＋"（已填充）.docx"，带"⚠ AI生成/提取，请人工核实"标注。
3. 映射同步（确认时同一事务内双写）：
   ① 全局映射库——只收"采纳且有平台编码"的行，失效旧映射同步停用；不采纳行、无映射行一律不入库；
   ② 知识库映射列表（6.1.7）——同步写入：关联模板＝本次模板、确认状态＝已确认、指标映射数＝本次入库条数；同一模板再次确认时更新同一条记录（不新建重复记录），指标映射数与更新时间随确认刷新；
   ③ 全局指标映射总表——每次确认导致全局库变化（新增/更新/失效停用）时，重新生成全局映射库当前全部有效条目的全量合并视图（三列），覆盖更新知识库中同一条记录（不堆积历史版本），列表置顶展示，关联模板列显示"全局"。
4. 完成提示带统计：共 X 项 · 采纳 Y · 无映射 Z · 不采纳 W。
5. 回填自检：结构指纹不变校验＋写入位置逐项复核，不通过则阻止发布。

### 流程 F：知识库映射表管理（对应：知识库 → 信息采集指标映射表，仅管理员）

1. 管理员点击左侧【信息采集指标映射表】菜单，右侧列表展示：映射表文件、关联模板、指标映射数、确认状态（已确认/待确认）、更新时间、操作。
2. 点击行内【下载】下载该映射表文件。
3. 点击行内【查看】弹出映射明细浮窗，以表格渲染该记录全部映射行，列为：附件定量指标名 / 平台对应指标名 / 平台对应指标编码。
4. 点击行内【删除】（仅管理员）删除该映射记录及其文件；删除仅移除知识库中的展示记录，不影响智能体全局映射库的既有匹配条目（全局库条目的清理走"平台指标失效→确认时停用"机制）。
5. 「全局指标映射总表」记录置顶展示（关联模板列显示"全局"）：可【查看】三列表格明细、可【下载】；系统自动维护，不提供【删除】（其余按模板的映射记录照旧可下载、可删除）。

## 4. 数据项清单（语义级）

| 数据项 | 业务含义 | 出现位置 | 来源方式 | 格式/约束 |
|---|---|---|---|---|
| 附件定量指标名 | 模板中提取的需填写定量指标名 | 确认表第 1 列 | 模板提取 | 只读 |
| 平台对应指标名 | 该行映射到的平台指标名 | 确认表第 2 列 | 映射表直填 / top3 下拉 / 手输 | 下拉候选带置信度，默认最高分 |
| 平台对应指标编码 | 平台指标唯一编码 | 确认表第 3 列 | 随匹配带出 | 只读 |
| 本期指标数据（XXXX年） | 本期数值 | 确认表第 4 列 | 平台自动填 / 手输 | 可空；人工值不被重匹配覆盖 |
| 上期指标数据（XXXX年） | 上期数值 | 确认表第 5 列 | 平台自动填 / 手输 | 可空；同上 |
| 匹配来源 | 该行匹配途径 | 确认表第 6 列 | 系统判定 | 枚举：映射表 / AI匹配 / 未匹配 |
| 是否采纳 | 该行是否用于填充与入库 | 确认表第 7 列 | 用户选择 | 默认采纳；不采纳＝不填充、不入库 |
| 置信度 | AI 候选可信程度 | top3 候选后显示 | AI 匹配输出 | 不占独立列 |
| 已修改 / 已刷新 | 行级状态标记 | 确认表行号旁 | 用户操作 / 服务端刷新触发 | 不占列；"已修改"持续到工作流结束，"已刷新"仅标本轮 |
| 本期年份 | 两期数值所属年份 | 数值列列头标注 | 消息明示 → 模板封面 → 当前系统年份 | 整表统一；前两者冲突则阻止并报错；上期＝本期-1 |
| 映射表（上传件） | 附件指标与平台指标的对照表 | 上传槽 | 📎 本地上传 / 🗂 知识库引用 | 三列 XLSX 且同时填写；恰好一个合规映射区域 |
| 映射记录（知识库列表） | 历次确认沉淀的映射表档案 | 知识库映射列表 | 最终确认时自动写入 | 关联模板＋确认状态＋指标映射数；同模板更新同一记录 |
| 全局指标映射总表 | 全局映射库全部有效条目的全量合并视图 | 知识库映射列表（置顶） | 每次确认随全局库变化自动重新生成 | 三列；覆盖更新同一条记录；关联模板显示"全局"；系统维护、不可删除 |

## 5. 状态与边界

| 场景 | 表现 |
|---|---|
| 全局映射库为空（首次使用） | 不强制上传映射表，全部行由大模型语义匹配，流程可跑通 |
| 上传映射表内部同名重复 | 解析时报错拒收（"附件定量指标名'××'重复"），用户改表再传 |
| 上传表行内名码自相矛盾 | 运行时经有效性校验判定为无效，进入大模型语义匹配 |
| 映射指向的平台指标已改名/删除 | 按未命中处理，该行进入大模型语义匹配；确认时该失效旧映射在全局库停用 |
| 多个附件指标名指向同一平台指标 | 合法（多对一），各行各自取数 |
| 手输平台指标名再匹配仍未命中 | 保留用户原文＋"未命中"标记，匹配来源＝未匹配；平台名/编码留空，数值可填可不填，不进映射表 |
| 数值为空 | 确认不因缺值报错；填充时跳过写入、单元格留空 |
| 消息明示年份与模板封面年度不一致 | 阻止并报错 |
| 确认表超过 6 行 | 仅预览前 6 行＋提示行；【查看/编辑完整表格】大窗承载全部编辑 |
| 并发冲突（他人同时确认） | 版本乐观锁，自动拉最新快照刷新重试 |
| 回填自检不通过（结构指纹变化/写入位置异常） | 阻止发布 |
| 采集表模式选错附件类型 | 选文件瞬间报错（仅支持 .docx/.xlsx）；模板槽/映射槽错配当场提示 |
| 知识库映射记录被删除 | 仅移除知识库展示记录与文件，不影响全局映射库既有条目 |
