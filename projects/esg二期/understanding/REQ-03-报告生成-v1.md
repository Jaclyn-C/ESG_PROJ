- 新增（v1 初版）：依据 2026-09-13 用户流程口述＋2026-09-14 对话逐项拍板＋主对话代码核实结论，建立报告生成需求的首版目标态——多轮任意时机攒料＋显式发起（FP-A）、数据选择联动（FP-B）、全局映射库前置的指标提取匹配（FP-C）、确认卡手动加行与来源列（FP-D）、映射沉淀全局库双写（FP-E）、知识库文件类型区分与消费（FP-F）、生成式撰写作交付（FP-G）。用户原话要点："用户可以从本地或者知识库上传参考文件或者提示词模板……也可以在下方通过数据选择的按钮，选择这份报告要使用的具体指标和数据，这些输入的内容不要求一次性输入完，可以在多轮对话完成，也不要求输入的时机。其实就和网页的版本的ai是类似的"；"我说的多轮、任意时机的意思是，用户可以随时再补充，不强制要求一次就说完"。

- 草稿期修订（2026-09-14）：报告映射表与采集表全局映射库**彻底分开**（两表、两套消费）——报告映射表为独立新增的后台资产，存「原文表述 / 用户自然语言 → 平台指标名＋编码」＋来源标签，消费方式＝作为参考文件注入大模型的提取/匹配过程（**软参考**，不做硬匹配拦截、不自动带出）；采集表硬匹配优先级（REQ-02 机制）完全不动。据此修订 FP-C（撤销全局库硬优先级表述，改为 top3 现状＋软参考注入）、FP-E（沉淀目标改为独立报告映射表，本期无管理 UI、不进 6.1.7 列表），入库表述长度上限由 40 字建议放宽至 100 字档（用途改为控制注入 token 规模，数值待确认）。依据：2026-09-14 对话，用户原话："在这个写报告阶段的映射表，和信息采集表的映射表要区分开，写报告的映射表存的是原文和平台指标的对应关系或者用户的自然语言和平台指标之间的映射关系，然后这个映射关系到时候会被当作一个参考文件丢给大模型，作为以后从文章中提取指标的参考（不是靠硬匹配）"。
- 草稿期修订二（2026-09-14）：FP-A 由「哑巴暂存＋显式按钮发起」改为「**正常对话＋语义触发＋按钮兜底**」——报告模式即正常 AI 对话（复用智能问答链路，AI 凭自身能力流式回答），废除"暂存期仅回已记录、不调 LLM 问答"的设计；用户消息具备"开始生成报告"意图即触发创建工作流（模型语义判定，实现由开发定），【开始生成】按钮降级为兜底入口；历轮附件/知识库引用/数据选择登记项累积为会话素材池，建流时全量带上；工作流终态后回到正常对话，可再次触发新建工作流（对话式迭代改写草稿不在本期，列待确认）。依据：2026-09-14 对话，用户原话："这里我想的是用户有类似请帮我生成。。开始生成。。等等的语义就可以开始写了，或者用户发送了什么东西就凭ai自己的能力回答一些内容（就和正常的网页版的例如deepseek/千问类似），我说的这个多轮只是说用户在模型回答过以后依然可以继续添加信息让模型再次回答"。
- 草稿期修订三（2026-09-14）：① 删除【开始生成】兜底按钮——发起方式只剩**语义触发**一种，语义漏判时模型按普通消息回答、用户换更明确的说法再次表达意图即可（依据：用户原话："按钮兜底（辅）：【开始生成】按钮/快捷指令，语义没接住时用；这个删除"）。② 新增「**已确认指标集（会话级）**」与**增量确认卡**——报告会话内历轮确认过的指标（含点选候选、数据选择登记、填写的数值）累积保留，每次生成作为数据供 AI 使用；每次语义触发后的确认卡只展示本轮新增项（已确认项不重复出现），报告任务为**累积式**而非每次从零再来；每轮确认终了映射照常增量入库（同一表述 upsert）。依据：用户原话："那个指标确认的窗口，如果确认过了，后面用户用补充了内容，比方说新上传了参考文献，是不是又会有新的确认弹窗（这个不会包括之前确认过的，但是之前确认的信息还是会保留，其实无论是确认过的信息，但是在指标选择那里点选的内容，都会被当作数据供ai使用）"。
- 草稿期修订四（2026-09-14）：澄清确认卡**三层语义**（修订三"增量确认卡"表述仅轮间成立，轮内为全量循环）——①**轮内＝全量循环确认**：一次触发的工作流内卡上有任何修改（改选/跳过/「其他」/【＋添加指标】）→ 重匹配 → 返回全量卡再确认，循环往复（沿用采集表 6.4.8 循环确认逻辑与现状代码行为，该层零改动）；②**终确＝落库点**：点【确认匹配】且本次无任何修改 → 本轮终确，落库＋更新已确认指标集＋进入生成；③**轮间＝增量**：再次语义触发的新一轮确认只含未确认过的新增项（上轮已落库/已确认的不重复出现）。依据：用户原话："我这个意思不是只展示增量的。比方说我这次确认卡内，手动新增了一些指标，会有二次确认，这次确认还是全量的，二次确认的时候我又不采用了一些指标，只要有修改就会让我再次确认，这些都是全量的。只有当我点击确认（就是所有都没有再次修改，然后就算是一次的映射表可以落库了）。用户可能会重新去发新的文本，或者指令，这时候是新的一轮确认，但是这一次的确认不会包括上一次已经落库的"。
- 草稿期修订五（2026-09-14）：**原型验收定稿**——①"素材池"定名"**上下文（Context）**"＝报告会话内累积的附件、知识库引用与数据选择登记项的集合，可增删，发起生成时整体作为报告上下文提供给模型（依据：用户原话："ok就叫上下文"）；②确认交互形态定为**与采集表完全同款**的确认表（会话内预览卡＋完整表格大窗，列集与交互照采集表，匹配来源徽标，**唯一功能差异＝大窗顶部"添加指标"行**；界面文案纯文字无符号）；③添加指标时机定为"**添加时不匹配、点【确认匹配】后才重匹配进二次确认**"（来源双标签"手动添加＋AI匹配"）；④附件-only 可发送：登记上下文并回确认语，无文字即无语义判定、不触发工作流；⑤语义判定细化＝每条文字消息都判定、宁可触发、无兜底按钮无二次确认弹窗；⑥三项边界定稿：重新生成每轮新结果卡追加落会话旧卡保留、数据选择与 AI 提取撞同一平台指标合并一行数据选择优先、全部行不采纳提示"至少采纳一项"不生成；⑦§8 待确认同步更新（删已定稿项、增输入区按钮去符号一项）。依据：2026-09-14 原型验收对话，用户原话："报告生成的弹窗里面展示的字段和信息采集表是完全一致的……唯一的不同就是报告这里可以添加指标""去掉所有表情，其他不变""新添加的指标名，只有在点击确认匹配了以后，才会去平台找到底新添加指标和平台哪一个指标是一个，然后返回二次确认，并且标注手动添加，AI提取"。
- 草稿期修订六（2026-09-14）：确认表数据列改造——删除"本期指标数据/上期指标数据"两列，改为**单列"数据"**：取值＝平台**收集年份中最新的年份**的已收集数据（口径同 6.2.6 数据选择"默认最新收集年份"）；数据选择登记行显示所选数值；该列保持可编辑。确认表与采集表的关系由"完全同款/唯一功能差异"修正为：列集与交互同款、**两处差异**——①大窗顶部"添加指标"行（原有）②数据列（采集表为本期/上期两列，报告为单列"数据"）。依据：2026-09-14 对话，用户原话："确认表格里的'本期指标数据'和'上期指标数据'都删除，就改成'数据'两个字，显示的是当年的年份（就是在数据库里收集年分里的最新的年的数据）"。

## 1. 背景与目标

### 1.1 现状（主对话代码核实）

1. 现有链路：报告模式（mode=report）下**首条消息（📎/🗂/粘贴/指令）立即创建工作流** → 知识检索 → LLM 提取 3–12 个定量指标 → 逐指标平台匹配 top3 → 确认卡（候选行含指标代码/名称/置信度%/当前值，默认最高分；可跳过；「其他」手输名 → 作为 new_samples 送回平台重匹配 → 二轮确认）→ 确认后 LLM 内联生成章节草稿 → 自建 docx（含红色"AI生成/提取，请人工核实"）→ 结果卡（可编辑纯文本、失焦保存＋乐观锁、复制全文、下载 .docx）。
2. 会话内有非终态工作流时拒绝新发起（activeWorkflow 门禁）。
3. 数据选择（REQ-20260908-04）是独立功能：结果只以表格卡片落会话展示，与报告工作流零联动。
4. 报告模式确认后不写任何映射：agent_template_mapping 表为死表（唯一写入点在采集表分支，全代码零读取）；真正被消费的复用机制是采集表的全局映射库 collection_indicator_mapping_library——采集表确认时双写全局库＋知识库映射列表，匹配时按「上传映射表 → 全局库 → 大模型语义匹配」优先级（合并机制现成；属采集表链路，报告链路不复用）。
5. 知识库文件类型功能半成品（REQ-20260831-04）：上传时必选 REFERENCE 参考文档 / PROMPT 提示词文档（前后端强校验），类型已透传 AI 契约；但 AI 选择弹窗不显示类型、知识库列表/卡片不显示类型（旧需求 6.1.3 标【已完成】属账实不符）、agent 侧无任何逻辑消费 file_type。
6. 报告生成现状即为**生成式撰写**（LLM 按用户要求＋确认事实＋证据写草稿），非"原文逐字保留替换数值"。
7. 建工作流接口已收多附件数组＋多知识库引用数组＋单条 message（≤50000 字符）；前端会话已有附件/引用暂存机制（采集表攒模板同款）。
8. 确认卡后端字段现成：候选行有 source_detail/mapping_source（枚举可扩展）；review 接口的 new_samples 支持任意新增行（前端目前仅「其他」选项用到）。

### 1.2 目标

把报告生成从"首条消息即发起的固定流程"改造为**与网页版 AI（deepseek/千问类）一致的正常对话体验**：用户随时发消息、AI 正常回答，附件/引用/数据选择在会话内累积为**上下文（Context）**；当用户消息表达"开始生成"意图（模型语义判定）时才创建报告工作流，进入既有的提取 → 匹配 → 确认 → 生成链路；同时打通数据选择与报告工作流的联动、让报告确认结果沉淀进独立的报告映射表（软参考资产）、让知识库文件类型真正被消费。撰写口径按用户拍板定为生成式撰写。

## 2. 功能点

- **FP-A 对话、上下文与语义触发（多轮任意时机，累积式）**：报告模式即正常 AI 对话——用户发任何内容（文字/📎/🗂），AI 凭自身能力正常流式回答（复用现有智能问答链路），废除"哑巴暂存"；历轮附件、知识库引用与数据选择登记项累积为会话级**上下文（Context）**（可增删；仅附件无文字也可发送，登记进上下文且不触发工作流）。报告模式**每条文字消息**都做生成意图判定（模型语义判定、实现由开发定），具备"开始生成报告"意图即触发创建报告工作流——**语义触发为唯一发起方式，无兜底按钮、无二次确认弹窗，宁可触发**；建流时带上上下文全部内容＋触发消息＋会话历史（聚合方式由开发定，受 5 万字符上限）。工作流状态机、确认表、生成、下载链路不动；终态后回到正常对话，再次语义触发开启**新一轮确认**（只含未确认过的新增项；表内修改仍走全量循环确认直至终确）、基于累积的已确认指标集重新生成。
- **FP-B 数据选择联动**：数据选择弹窗确认后，除落展示卡片外，同时把选中项登记为会话级"报告数据暂存"（进上下文）；发起时随建工作流增传 data_selections[]（指标编码/名称/年份/维度对象/数值）；agent 侧注入候选表时直接置为已匹配行（跳过提取/匹配），mapping_source 扩展枚举 data_selection；确认表匹配来源徽标含 **AI 提取 / 数据选择 / 手动添加**三档；与 AI 提取撞同一平台指标时合并一行、数据选择优先（定稿）。
- **FP-C 指标提取与匹配（核心零改＋报告映射表软参考）**：提取 → 平台对照 → top3＋当前值 → 都不对则自定义再匹配，沿用现状。新增：报告映射表作为参考文件注入提取/匹配 prompt——**软参考**，辅助模型从文章中识别表述与平台指标的对应关系，不做硬匹配拦截、不自动带出行；注入按相关性取子集控制规模（具体由开发定）。
- **FP-D 确认表（采集表同款＋两处差异）**：确认表与采集表 6.4.7 列集与交互同款——会话内预览卡（超 6 行显前 6 行＋提示行＋【查看/编辑完整表格】）＋大窗承载全部编辑（副本编辑、点确认才应用、关闭/取消丢弃）；top3 下拉带置信度 0.5 过滤、默认最高分、都不对可手动输入，行尾"已修改/已刷新/低置信"状态列；匹配来源徽标含 AI 提取/数据选择/手动添加；**与采集表两处差异**：①大窗顶部"添加指标"行——添加时不匹配（新行仅素材指标名＋来源"手动添加"＋状态"待匹配"），点【确认匹配】后才重匹配进二次确认（双标签"手动添加＋AI匹配"；未命中则"手动添加＋未匹配"、可继续手输；new_samples 通道后端现成）；②数据列——采集表为本期/上期两列，报告为**单列"数据"**（取平台收集年份中最新的年份的已收集数据，数据选择行显示所选数值，可编辑）；界面文案纯文字、无符号。
- **FP-E 映射沉淀（独立报告映射表）**：报告工作流**终确**时，对「**采纳且有平台编码**」的行写入**独立的报告映射表**（与采集表全局映射库彻底分开，两表两套消费）；**不分 AI 提取/手动添加，一律入库**（否则同一文章下次无法复用确认结果）。报告映射表存两类映射：文章语句→平台指标、用户自然语言→平台指标，条目结构＝表述 → 平台指标名＋编码＋来源标签；纯后台资产，本期无管理 UI、不出现在 6.1.7「信息采集指标映射表」列表（该列表属采集表）。护栏：①入库打来源标签（文章提取/手动添加/自然语言）②入库表述长度上限建议 100 字档、用途＝控制注入 token 规模，整段长句不入库（数值待确认，见 §8）。
- **FP-F 知识库文件类型区分与消费**：①AI 选择弹窗文件行加类型标识（参考文档/提示词文档）②知识库列表/卡片补类型列（顺带修复旧需求 6.1.3 账实不符）③agent 报告工作流按 file_type 分流：PROMPT 文档文本进"要求/指令"侧（注入提取与生成 prompt），REFERENCE 进"素材"侧（提取指标＋证据）。
- **FP-G 报告生成交付（沿用现状，零改）**：确认后 LLM 按用户要求（聚合建流前会话内全部用户消息）生成式撰写；纯文本草稿、可编辑（失焦保存＋乐观锁）、复制全文、下载 .docx（含 AI 核实标注）。

## 3. 交互流程（点击级）

### 流程 A：对话、上下文累积与语义发起（对应：全局 AI 助手对话窗口·报告生成模式）

1. 点击【报告生成】切换模式，顶部出现模式提示条，助手发送欢迎语说明用法（沿用旧 6.3.1）。
2. **正常对话**：用户可随时发送任意内容——文字（要求、普通补充信息、提问，或用自然语言点名报告要写的指标名）、【📎】本地参考文件/提示词模板、【🗂】知识库引用（弹窗内文件行带类型标识，见流程 E）；AI 凭自身能力正常流式回答（复用现有智能问答链路，附件与引用随该轮消息参与回答），体验与网页版 AI（deepseek/千问类）一致——用户原话："或者用户发送了什么东西就凭ai自己的能力回答一些内容（就和正常的网页版的例如deepseek/千问类似）"。**仅附件无文字也可发送**（全局规则 6.2.4）：发送后文件登记进上下文，AI 回"已收到《××》，已登记为报告素材"类回复；**无文字即无语义判定，纯附件不触发工作流**。
3. **上下文（Context）累积**：报告会话内历轮的 📎 附件、🗂 知识库引用与数据选择登记项累积为会话级**上下文（Context）**——报告会话内累积的附件、知识库引用与数据选择登记项的集合，可增删；正常对话轮发送后附件照常随轮发送，上下文保留（定名依据用户原话："ok就叫上下文"）。
4. （可选）点击输入区【数据选择】按钮打开弹窗（现有功能，配置交互不变），确认后结果表格卡片照旧落会话展示，同时所选指标与数值登记进上下文（即 FP-B 的会话级"报告数据暂存"）。
5. **语义触发发起（唯一发起方式，无兜底按钮）**：报告模式**每条文字消息**都做生成意图判定（模型语义判定、实现由开发定），宁可触发——误判可取消、漏判用户重述，无二次确认弹窗（见 §6）。用户消息具备"开始生成报告"意图（如"请帮我生成…""开始生成…"）即由该条消息触发创建报告工作流，用户原话："这里我想的是用户有类似请帮我生成。。开始生成。。等等的语义就可以开始写了"。建流时带上上下文全部内容＋触发消息＋会话历史（聚合方式由开发定，受单条消息 ≤50000 字符上限约束）。
6. 发起后进入固定流程：提取 → 确认表（流程 B）→ 生成（流程 C）；发起后如需再补充，走确认表大窗"添加指标"行。**已确认指标集（会话级）**：报告会话内历轮确认过的指标（含点选候选、数据选择登记、填写的数值）累积保留，后续每次生成都作为数据供 AI 使用（用户原话："无论是确认过的信息，但是在指标选择那里点选的内容，都会被当作数据供ai使用"）。生成后继续补充（新参考文献/新要求）→ 正常对话回答 → 再次语义触发 → **新一轮确认（只含未确认过的新增项；表内修改仍走全量循环确认直至终确，见流程 B）** → 基于累积全集重新生成草稿——报告任务为累积式，不是每次从零再来（用户原话："我说的这个多轮只是说用户在模型回答过以后依然可以继续添加信息让模型再次回答"）；重新生成每轮新结果卡追加落会话、旧卡保留（定稿）；已生成草稿的修改沿用结果卡手动编辑（对话式迭代改写草稿不在本期，见 §8）。

### 流程 B：指标提取、匹配与确认（对应：会话内确认表预览卡＋完整表格大窗）

1. 工作流创建后执行知识检索与提取：**提取与确认范围＝新素材提取出且不在会话级已确认指标集内的项**（首轮即全部提取项；已确认项不重复出现、继续生效，判重键暂定按平台指标，见 §8）。LLM 从素材侧（REFERENCE 文档与粘贴内容）提取定量指标（3–12 个）；PROMPT 文档文本进要求侧，注入提取与生成 prompt（深度暂定，见 §8）。
2. 匹配方式：大模型语义匹配（top3，现状）＋**报告映射表作为参考文件注入提取/匹配 prompt（软参考）**——辅助模型识别文章表述与平台指标的对应，不做硬匹配拦截、不自动带出行；注入时按相关性取子集控制规模（具体由开发定）。采集表侧的「上传映射表 → 全局库 → 语义匹配」硬优先级属 REQ-02 机制，报告链路不使用。
3. 提取完成后助手回复"解析完成：提取到 × 个指标"，出现**确认表——与采集表 6.4.7 同款形态（列集与交互同款，两处差异）**（用户原话："报告生成的弹窗里面展示的字段和信息采集表是完全一致的……唯一的不同就是报告这里可以添加指标"——后又增数据列差异，见下）：
   - **会话内预览卡**：超过 6 行仅显示前 6 行＋提示行＋【查看/编辑完整表格】；**大窗**承载全部编辑——副本编辑、点确认才应用、关闭/取消丢弃修改；
   - **列集与交互照采集表**：序号 / 素材指标名（提取项或手动添加的表述，只读）/ 平台对应指标名（top3 下拉带置信度，候选经 0.5 阈值过滤、默认最高分、都不对可手动输入）/ 平台对应指标编码（只读，随匹配联动）/ **数据（单列）**——取平台**收集年份中最新的年份**的已收集数据（口径同 6.2.6 数据选择"默认最新收集年份"），平台带出、可编辑；数据选择登记行显示所选数值 / 匹配来源（徽标：AI 提取 / 数据选择 / 手动添加，含双标签，见第 5 步）/ 是否采纳 / 行尾状态列（已修改·已刷新·低置信，口径同采集表）；
   - 数据选择登记的行直接置为已匹配行（显示所选数值），匹配来源＝数据选择；与 AI 提取撞同一平台指标时**合并为一行、数据选择优先**（定稿）；
   - **与采集表两处差异**：①大窗顶部"添加指标"行（见第 5 步）；②数据列——采集表为本期/上期两列，报告为单列"数据"（取最新收集年份）（修订六定稿）；
   - 界面文案纯文字、无符号（用户原话："去掉所有表情，其他不变"）。
4. 平台候选都不对：在"平台对应指标名"列手动输入指标名 → 随【确认匹配】作为新样本送回平台重匹配 → 二次确认（**全量表**，现状行为）再核。
5. **添加指标（与采集表差异①）**：在大窗顶部"添加指标"行输入指标名或参考文件/模板里的表述原文；**添加时不匹配**——新行仅有素材指标名＋匹配来源"手动添加"＋行尾状态"待匹配"；点【确认匹配】后才与本次其他修改一起重匹配 → 二次确认（全量表）；此时该行 top3 呈现与 AI 提取行一致，匹配来源为双标签"**手动添加＋AI匹配**"；平台未命中 → "手动添加＋未匹配"、可继续手输（用户原话："新添加的指标名，只有在点击确认匹配了以后，才会去平台找到底新添加指标和平台哪一个指标是一个，然后返回二次确认，并且标注手动添加，AI提取"）。
6. 不采用某项：选"不采用（跳过）"，该项不参与生成事实、不入映射库。
7. 点击【确认匹配】：手动输入了指标名但未填写则提示并定位到输入框、不关闭。**轮内循环**：表上存在任何修改（改选候选/切跳过/手动输入/添加指标）→ 重匹配 → 返回**全量确认表**（本轮工作流全部指标项）再确认，只要有修改就再次全量确认、循环往复（沿用采集表 6.4.8 循环确认逻辑与现状代码行为，该层零改动）——用户原话："只要有修改就会让我再次确认，这些都是全量的"。**终确＝落库点**：点【确认匹配】且本次无任何修改 → 本轮终确，确认表锁定，同时发生三件事——①本轮映射写入报告映射表（采纳且有平台编码的行，见流程 D）②会话级已确认指标集更新 ③进入生成（基于累积全集）；全部行均不采纳 → 提示"至少采纳一项"、不进入生成（定稿）；助手回复采纳/调整/跳过计数汇总。

### 流程 C：报告生成与交付（对应：会话内报告结果卡）

1. 确认后助手显示"正在生成报告…"。
2. LLM 按用户要求**生成式撰写**：要求侧＝建流前会话内全部用户消息（含 PROMPT 文档），事实侧＝**累积的已确认指标集**（历轮确认的指标与数值，含点选候选、数据选择登记与填写数值），并引用素材证据。
3. 完成后出现报告结果卡：标题旁"AI生成/提取，请人工核实"角标；正文为可编辑纯文本（点击即改，失焦保存＋乐观锁）；【复制全文】复制到剪贴板；【下载 .docx】下载 Word 草稿（文件含同样 AI 标注）。

### 流程 D：映射沉淀（终确自动执行，无用户操作）

1. 报告工作流**终确**（一次点【确认匹配】且无任何修改，见流程 B 第 7 步）时，对「采纳且有平台编码」的行写入**独立的报告映射表**，每轮终确各自落库一次；采集表全局映射库与知识库映射列表（6.1.7）完全不涉及。
2. 入库不分来源：AI 提取行与手动添加行一律入库。
3. 报告映射表存两类映射：文章语句→平台指标、用户自然语言→平台指标；条目结构＝表述 → 平台指标名＋编码＋来源标签；纯后台资产，本期无管理 UI、不出现在 6.1.7「信息采集指标映射表」列表。
4. 护栏：①每条入库带来源标签（文章提取/手动添加/自然语言，枚举命名待确认）②入库表述长度上限建议 100 字档（用途＝控制注入 token 规模），整段长句不入库（数值待确认，见 §8）。
5. 消费语义：后续任务的提取/匹配 prompt 把报告映射表作为参考文件注入（软参考——"作为以后从文章中提取指标的参考（不是靠硬匹配）"，用户原话）；模型参考后产出的候选仍走 top3＋确认表（误配可改）；同一文章措辞漂移时不保证参考生效 → 语义匹配兜底 → 确认后新措辞再入库，逐步收敛。
6. 累积式任务多轮生成时，每轮终确照常增量入库，同一表述按 upsert 更新（不重复堆积）。

### 流程 E：知识库文件类型展示（对应：AI 知识库选择弹窗＋知识库列表/卡片）

1. 报告模式点【🗂】打开 AI 选择弹窗：每个文件行显示类型标识（参考文档 / 提示词文档）。
2. 知识库模块列表/卡片补类型列（修复旧需求 6.1.3 标【已完成】但实际未显示的账实不符；是否纳入本期见 §8）。

## 6. 状态与边界

| 场景 | 表现 |
|---|---|
| 报告模式下发文字消息（默认情形） | 正常 AI 流式回答，附件与知识库引用随该轮消息参与回答；每条文字消息都做生成意图判定 |
| 仅发送附件（无文字） | 文件登记进上下文，AI 回"已收到《××》，已登记为报告素材"类回复；无文字不做语义判定、不触发工作流 |
| 语义误触发（普通消息被判为要生成） | 误判可接受（代价低）：可取消工作流（沿用现有 cancel 能力），或料已足够时顺势继续确认；触发消息内容不丢失（已进建流上下文，上下文保留）；**不设"是否开始生成"二次确认弹窗**，意图判定倾向宁可触发（见拍板⑩） |
| 语义漏触发（想生成但未建流） | 模型按普通消息回答；用户换更明确的说法再次表达生成意图即可 |
| 确认表等非终态工作流进行期间发消息 | 正常 AI 回答、不新建工作流（新建仍受 activeWorkflow 门禁，沿用现状；终态或取消后放行再次发起） |
| 工作流终态或取消后 | 回到正常对话；可继续补充信息让模型再回答，或再次语义触发开启新一轮确认（只含新增项）与累积式重新生成 |
| 再次语义触发（会话已有已确认指标集） | 新一轮确认只含未确认过的新增项（新素材提取且不在已确认集内）；已确认项不重复出现、继续生效 |
| 轮内确认表出现任何修改 | 重匹配后返回**全量确认表**（本轮工作流全部指标项）再确认，循环往复（沿用采集表 6.4.8 与现状代码行为） |
| 终确（点【确认匹配】且本次无任何修改） | 本轮映射落库（报告映射表）＋已确认指标集更新＋进入生成（基于累积全集） |
| 确认表全部行均不采纳 | 提示"至少采纳一项"，不进入生成（定稿） |
| 重新生成时旧草稿的处理 | 每轮新结果卡追加落会话，旧卡保留（定稿） |
| 数据选择与 AI 提取指向同一平台指标 | 合并为一行，数据选择优先（定稿） |
| 累积文字超 5 万字符 | 沿用现有超长提示"当前提问内容过长，请拆分后重试" |
| 未做任何数据选择就发起 | 数据选择暂存为空，正常走提取/匹配 |
| 报告映射表条目 | 仅作模型参考注入，不硬匹配、不自动带出行；候选仍走 top3＋确认表（误配可改） |
| 同一文章措辞漂移导致参考失效 | 语义匹配兜底；确认后新措辞再入库，逐步收敛 |
| 生成内容超上下文限制 | 沿用旧 §6.3.3 口径：会话中断、提示重新发起，已生成内容须用户自行复制保存 |
